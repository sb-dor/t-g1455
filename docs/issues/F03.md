# `GlassLedger.read` counts resting control drops (materialize/presence 0) as captured, though the host captures nothing for them

## Summary

A resting `GlassSwitch` or `GlassSlider` knob is a `GlassSurface` at `materialize: 0`, on purpose, and the host knows it draws nothing and captures nothing for it. `GlassLedger.read` counts it as a captured surface anyway.

The host side, `glass_host.dart` (lines 1128-1131):

```dart
      // Nor is a surface at presence zero, which draws nothing: capturing it
      // would size the atlas — and, for a finish of its own, the divisor — for
      // glass that is not there (a control's drop at rest).
      if (record != null && record.readsCapture && record.presence > 0 && record.materialize > 0) {
```

The ledger side, `glass_ledger.dart` (lines 425-428, in `GlassLedger.read`):

```dart
      if (!r.readsCapture) {
        continue;
      }
      capturedCount++;
```

`readsCapture` (line 74) is `tier.readsBackdrop && !declared`. It does not look at `materialize` or `presence`, although the record's own docs say a surface at zero "draws nothing and is captured for nothing" (`materialize`, lines 76-78) and "the host captures nothing for it" (`presence`, lines 80-84).

The resting knob is registered on purpose: `glass_controls.dart` lines 17-18 describe the drop as "a [GlassSurface] at `presence` 0 at rest — drawing nothing and **captured for nothing**", and the knob is built with `materialize: lift` (line 189; `lift` is 0 at rest). The switch page says the same thing from the user's side:

> At rest the knob and the track are ordinary paint, not glass. The drop exists only while the switch is held, so a page with twenty switches costs the glass nothing until someone touches one.
> — https://g1455.plugfox.dev/components/switch

That sentence is true of what is drawn and of what the host captures. The ledger disagrees with it: it reports `capturedSurfaceCount == 20` for twenty resting switches.

## Environment

- g1455 0.2.0, Flutter 3.47.1 stable
- iPhone 17 Pro simulator, iOS 26.5, Impeller (Metal), debug build (the `20 surfaces, 20 captured, 0.052 screens` figures below are from here)
- The same counts also reproduce in a widget test (`flutter test`, 800x3000 view): 20 resting switches give `surfaceCount` 20 and `capturedSurfaceCount` 20; 10 resting sliders give 10 and 10.

## Steps to reproduce

1. Put 20 `GlassSwitch`es in a grid under a `GlassHost`, and don't touch them.
2. Read the ledger:
   `GlassScope.maybeOf(context)?.read(viewSize: MediaQuery.sizeOf(context), model: GlassHardware.detect().surfaceCostModel)`.
3. Compare `capturedSurfaceCount` with what the host captures (nothing, per `glass_host.dart:1131`).

The program below does this once a second and shows the numbers on screen. `--dart-define=SWITCHES=0 --dart-define=SLIDERS=10` runs the same check with ten resting `GlassSlider`s, which build the same drop (`_drop(...)` at `glass_controls.dart` line 1081).

## Expected behaviour

`capturedSurfaceCount == 0` for twenty resting switches, the same set of surfaces the host captures for. A page of resting switches would read `0` captured, as the doc on `GlassLoad.capturedSurfaceCount` ("How many of them read a proxy, which is how many the capture is for", `glass_ledger.dart` line 519) implies.

## Actual behaviour

| Controls at rest | `surfaceCount` | `capturedSurfaceCount` | `screensOfGlass` |
|---|---|---|---|
| 20 switches | 20 | 20 | 0.052 (device) |
| 0 | 0 | 0 | 0.000 |

The whole program, including the ledger read, is below.

```dart
// F03: GlassLedger.read counts a control's resting drop as captured.
//
// A resting GlassSwitch (or GlassSlider) knob is a GlassSurface at
// materialize 0, by design (glass_controls.dart:17-19, :184-189). The host
// captures nothing for such a surface (glass_host.dart:1131 keeps only
// `readsCapture && presence > 0 && materialize > 0`), but GlassLedger.read
// counts it as captured, because it tests only `readsCapture`
// (glass_ledger.dart:425, :74), which ignores materialize and presence.
//
// This program reads the ledger once a second and shows the result: with
// twenty resting switches, capturedSurfaceCount is 20; the host captures none.
//
// Run:
//   flutter run -t repro/f03_switch_at_rest_surfaces.dart
//   flutter run -t repro/f03_switch_at_rest_surfaces.dart --dart-define=SWITCHES=0
//   flutter run -t repro/f03_switch_at_rest_surfaces.dart --dart-define=SWITCHES=0 --dart-define=SLIDERS=10
//   flutter run -t repro/f03_switch_at_rest_surfaces.dart --dart-define=OUTLINES=true
//
// OUTLINES is context only: debugPaintGlassSurfaces outlines every registered
// surface, and the resting knob is registered on purpose.
import 'dart:async';

import 'package:flutter/material.dart';
import 'package:g1455/g1455.dart';

const int kSwitches = int.fromEnvironment('SWITCHES', defaultValue: 20);
const int kSliders = int.fromEnvironment('SLIDERS');

Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await GlassHost.precache();
  debugPaintGlassSurfaces = const bool.fromEnvironment('OUTLINES');
  runApp(const ReproApp());
}

class ReproApp extends StatelessWidget {
  const ReproApp({super.key});

  @override
  Widget build(BuildContext context) => MaterialApp(
    debugShowCheckedModeBanner: false,
    theme: ThemeData(brightness: Brightness.dark),
    builder: (BuildContext context, Widget? child) =>
        GlassHost(backdrop: const Color(0xFF1A1D29), child: child!),
    home: const Scaffold(
      backgroundColor: Color(0xFF1A1D29),
      body: SafeArea(child: ReproPage()),
    ),
  );
}

class ReproPage extends StatefulWidget {
  const ReproPage({super.key});

  @override
  State<ReproPage> createState() => _ReproPageState();
}

class _ReproPageState extends State<ReproPage> {
  final List<bool> _on = List<bool>.generate(kSwitches, (int i) => i.isEven);
  final List<double> _level = List<double>.generate(
    kSliders,
    (int i) => 0.2 + 0.6 * (i % 5) / 4,
  );
  Timer? _timer;
  String _ledger = 'reading…';

  @override
  void initState() {
    super.initState();
    _timer = Timer.periodic(const Duration(seconds: 1), (_) => _read());
  }

  @override
  void dispose() {
    _timer?.cancel();
    super.dispose();
  }

  void _read() {
    final GlassLoad? load = GlassScope.maybeOf(context)?.read(
      viewSize: MediaQuery.sizeOf(context),
      model: GlassHardware.detect().surfaceCostModel,
    );
    final String text = load == null
        ? 'no ledger'
        : '$kSwitches switches + $kSliders sliders at rest\n'
              'surfaceCount ${load.surfaceCount}\n'
              'capturedSurfaceCount ${load.capturedSurfaceCount}'
              '  (the host captures none of these)\n'
              'screensOfGlass ${load.screensOfGlass.toStringAsFixed(3)}';
    debugPrint('F03 ${text.replaceAll('\n', ' | ')}');
    setState(() => _ledger = text);
  }

  @override
  Widget build(BuildContext context) => Column(
    crossAxisAlignment: CrossAxisAlignment.stretch,
    children: <Widget>[
      Padding(
        padding: const EdgeInsets.all(16),
        child: Text(_ledger, style: const TextStyle(color: Colors.white)),
      ),
      if (kSwitches > 0)
        Expanded(
          child: GridView.count(
            crossAxisCount: 4,
            padding: const EdgeInsets.all(16),
            children: <Widget>[
              for (int i = 0; i < kSwitches; i++)
                Center(
                  child: GlassSwitch(
                    value: _on[i],
                    onChanged: (bool v) => setState(() => _on[i] = v),
                  ),
                ),
            ],
          ),
        ),
      if (kSliders > 0)
        Expanded(
          child: ListView(
            padding: const EdgeInsets.all(16),
            children: <Widget>[
              for (int i = 0; i < kSliders; i++)
                GlassSlider(
                  value: _level[i],
                  onChanged: (double v) => setState(() => _level[i] = v),
                ),
            ],
          ),
        ),
    ],
  );
}
```

## Question

1. Should `GlassLedger.read` skip a record with `materialize <= 0` or `presence <= 0` when it counts `capturedSurfaceCount` and `capturedRectAreaLogical`, the way `glass_host.dart:1131` does when it builds the capture? Today the ledger's captured set and the host's captured set differ by exactly these surfaces.
2. Separately: should `surfaceCount`, `screensOfGlass` and the fragmentation excess (`fragmentationExcessCycles`, which follows `surfaceCount * surfaceCount`) include zero-materialize surfaces? `surfaceCount` is documented as "How many surfaces could say where they are, on every rung" (`glass_ledger.dart` lines 515-517), so counting them may be intended, but a page of twenty resting switches then reads as twenty surfaces of tax, and the switch page says it costs nothing.
